Useful Git Commands

Practical commands for everyday Git work. Steps that depend on GitHub are explicitly labelled.

Clone a repository

Open the terminal in Visual Studio Code and choose the parent directory before cloning:

cd C:\projects
git clone <repository-url>

GitHub example: include the account name in the HTTPS URL when you work with multiple GitHub accounts:

git clone https://username@github.com/username/repository-name.git

Open the checkout in Visual Studio Code and inspect the configured remote:

cd repository-name
code .
git remote -v

The username in the URL identifies the intended account; authentication is handled separately, normally by Git Credential Manager.

Change the origin remote URL

When a repository is renamed or moved, update its local origin remote. These are standard Git commands; the URL below is a GitHub example.

git remote -v
git remote set-url origin https://github.com/username/new-repository-name.git
git remote -v
git fetch origin

GitHub alternatives: choose either an HTTPS URL with an explicit username or an SSH URL (not both):

# HTTPS, with a specific GitHub account:
git remote set-url origin https://username@github.com/username/new-repository-name.git

# SSH:
git remote set-url origin git@github.com:username/new-repository-name.git

GitHub note: GitHub may redirect an old repository URL after a rename, but updating the local remote keeps it clear and current.

Reset local main after a force-push

If the remote main branch was rewritten (for example, by a force-push), your local main may still point to the old history. To make your local main exactly match the latest origin/main, run:

git switch main
git fetch origin
git reset --hard origin/main
  • git switch main selects your local main branch. Check that you are on the correct branch before resetting.
  • git fetch origin downloads the current remote branch information, including any rewritten history.
  • git reset --hard origin/main moves the current local branch to the same commit as origin/main, and resets its index and tracked working files to match.

Warning: This discards uncommitted changes to tracked files and removes local commits from the branch if they are not part of the new remote history. It does not delete untracked files by default. It does not change the remote repository.

Before resetting, use git status to check for local changes. If you need to keep the old local commits, create a backup branch first:

git branch backup/main-before-reset

A backup branch preserves committed history, not uncommitted file changes; save or stash those separately before running reset --hard.

Create a tag using GitHub

GitHub web interface: Git tags are a standard Git feature, but the following steps are specific to GitHub.

  1. Open the repository on GitHub and select Releases.
  2. Select Draft a new release.
  3. Enter a tag name, select Create new tag and choose the target branch or commit.
  4. Publish the release.

You can remove the release afterwards and keep the tag. When deleting the release, do not select the option to delete its associated tag.

Example tag names:

daily/20260729
milestone/first-working-build
