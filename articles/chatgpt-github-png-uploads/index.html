ChatGPT and GitHub: handling PNG uploads

During work on a Marp presentation in a private GitHub repository, ChatGPT struggled with PNG uploads: repeated attempts, unexplained delays, and eventual success.

Memo Investigating Created: 01 Nov 2026 Updated: 01 Nov 2026

Problem

During work with ChatGPT on a Marp presentation stored in a private GitHub repository, text and presentation-source changes went relatively smoothly, but uploading a PNG image was unexpectedly difficult and slow. ChatGPT kept trying different approaches, appeared to get stuck in the process, and even when an upload eventually succeeded, it took an unusually long time without a clear explanation.

This was mainly an issue during the Marp presentation work, not something first noticed while building this Hugo website.

GitHub itself supports PNG files. The upload was possible, but the reason for ChatGPT’s repeated attempts and unexplained delays in this workflow has not been established.

Current workaround

For now, the working approach is to save the PNG to Google Drive, then download it and manually add it to the GitHub repository.

This preserves the image but adds a manual step to a workflow that otherwise supports direct text updates.

Technical reference

openai/codex #45448 — Allow binary image uploads from ChatGPT attachments to GitHub explains a similar technical problem: the GitHub connector can write a Base64-encoded image using the Git blob API, but the attached image bytes must first be read and encoded. In the reported session, the execution environment needed for that step was unavailable.

The report also describes successful uploads in other sessions. It provides useful background on the technical steps involved, but does not establish the cause of the repeated attempts or slowness observed during the Marp presentation work.

Current conclusion

PNG uploads did eventually work, but the process involved repeated attempts and unexplained delays. The issue is therefore not that uploading is impossible; it is that the experience in this Marp workflow was unnecessarily cumbersome and slow. The cause is unknown, and this experience alone does not establish how the workflow behaves in general.

Google Drive followed by a manual upload remains a practical fallback when the direct approach gets stuck. Other methods should only be added here after they have been tested.
